## Install and run

Use Python 3.11; tested package versions are in `results/environment.txt`. Run these commands from the repository folder in PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\start_api.ps1 -BindAddress 0.0.0.0
```

Place the official dataset at `../Student folder` with `train/` and `student_test/` folders, or set `PATHSNAP_DATA_ROOT` to its location. Models are loaded from `artifacts/`; use compatible scikit-learn versions or retrain.

Open `http://127.0.0.1:8000` on the model laptop. On a second laptop on the same trusted network, open `http://MODEL_LAPTOP_IP:8000`, enter that address in **MODEL SERVER**, connect, select a trip and reconstruct the route. Port 8000 must be accessible. API documentation is at `/docs`; endpoints are `GET /health`, `GET /api/trips` and `POST /api/predict`.

For organiser-supplied reserved trips, set `PATHSNAP_EVALUATOR_ROOT` to that partition before starting the server. Each trip needs matching `.track`, `.nodes`, `.arcs` and optional server-only `.route` files. References are opened for scoring after prediction; reference labels and geometry are not returned to the UI.

## Reproduce experiments

```powershell
.\.venv\Scripts\python.exe -m pathsnap.experiment --data "..\Student folder" --trials 10
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Experiments use 80 training trips and 10 student-test trips. Reserved evaluator data was not supplied or used. Three-fold GroupKFold keeps complete trips apart; scaling is fitted within each training fold. Model selection uses mean per-trip observation-level macro F1. Student-test results are not used for model selection.

Twelve directed road candidates and twelve features describe geometry, heading, movement and connectivity. Arc IDs are not learned features. Training samples at most 350 observations per trip with seed 181126. Bayesian search uses a Gaussian-process surrogate and expected improvement over ten trials. Viterbi uses directed network distances and starts new components for gaps over 30 seconds or unreachable transitions.

## Metric limitations and verification

Route files contain traversed arcs rather than native GPS-point labels. Monotone geometric alignment derives proxy reference labels for training and scoring. Pointwise scores measure agreement with these derived labels and may be optimistic because geometry also appears in the model features.

Macro F1, precision and recall are averaged per trip; accuracy and log loss are observation weighted. Candidate misses count as errors. Candidate scores are normalised heuristic HMM emissions, without guaranteed calibration. Route continuity measures directed reachability within the search limit; arc-set F1 measures coverage rather than traversal order. Distances use a local equirectangular approximation.

`results/` retains seeds, folds, configurations and measured results. Runtime varies by machine. Handler validation and live HTTP checks are recorded separately; neither establishes reserved-trip evaluation or a completed two-laptop demonstration.
